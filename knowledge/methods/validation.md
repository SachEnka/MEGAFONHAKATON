# План проверки

`outputs/validation_plan.md`:

1. **Ожидаемое изменение** — метрика или наблюдаемое поведение.
2. **С чем сравниваем** — база (прошлый период, контроль, A/B).
3. **Срок наблюдения**.
4. **Нежелательные последствия** — что мониторим как «стоп».
5. **Порог решения** — при каком результате усиливаем / откатываем / пересматриваем стратегию.
6. **Данные** — откуда возьмём (и пробелы open-data).

План должен быть исполнимым руководителем продукта, не «лабораторным идеалом».
